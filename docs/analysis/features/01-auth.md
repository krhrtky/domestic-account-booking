# 機能仕様書: 認証・ユーザー管理

## 概要

ユーザーの登録、ログイン、ログアウト、セッション管理を担う機能群。

## ユースケース

### UC-AUTH-001: 新規ユーザー登録

**アクター**: 未登録ユーザー

**事前条件**:
- ユーザーがサインアップページにアクセスしている
- 同一メールアドレスのアカウントが存在しない

**フロー**:
1. ユーザーが名前、メールアドレス、パスワードを入力
2. ユーザーが「登録」ボタンをクリック
3. システムが入力値をバリデーション
4. システムがパスワードをハッシュ化
5. システムがユーザーレコードを作成
6. システムがセッションを開始
7. ユーザーがダッシュボードにリダイレクト

**事後条件**:
- ユーザーアカウントが作成されている
- ユーザーがログイン状態になっている

**異常系**:
- E1: メールアドレスが既に使用されている → エラー「このメールアドレスは既に使用されています」
- E2: パスワードが弱い → エラー「パスワードは8文字以上で入力してください」
- E3: 必須項目が未入力 → 該当フィールドにエラー表示

### UC-AUTH-002: ログイン

**アクター**: 登録済みユーザー

**事前条件**:
- ユーザーがログインページにアクセスしている
- 有効なアカウントが存在する

**フロー**:
1. ユーザーがメールアドレスとパスワードを入力
2. ユーザーが「ログイン」ボタンをクリック
3. システムが認証情報を検証
4. システムがセッションを開始
5. ユーザーがダッシュボードにリダイレクト

**事後条件**:
- ユーザーがログイン状態になっている

**異常系**:
- E1: メールアドレスが未登録 → エラー「メールアドレスまたはパスワードが正しくありません」
- E2: パスワードが不正 → エラー「メールアドレスまたはパスワードが正しくありません」
- E3: レート制限超過 → エラー「ログインの試行回数が上限を超えました。15分後に再試行してください」

### UC-AUTH-003: ログアウト

**アクター**: ログイン済みユーザー

**フロー**:
1. ユーザーが「ログアウト」ボタンをクリック
2. システムがセッションを破棄
3. ユーザーがランディングページにリダイレクト

**事後条件**:
- セッションが無効化されている
- ユーザーが未認証状態になっている

### UC-AUTH-004: 保護リソースへのアクセス

**アクター**: 任意のユーザー

**事前条件**:
- ユーザーが保護されたページにアクセスしようとしている

**フロー（認証済み）**:
1. システムがセッションを検証
2. セッションが有効ならリソースを表示

**フロー（未認証）**:
1. システムがセッションを検証
2. セッションが無効または存在しない
3. ユーザーをログインページにリダイレクト

## データモデル

```typescript
interface User {
  id: string          // UUID
  name: string        // ユーザー名
  email: string       // メールアドレス（一意）
  password_hash: string // bcryptハッシュ
  group_id: string | null // 所属グループID
  created_at: Date
  updated_at: Date
}
```

## セキュリティ要件

| 要件ID | 内容 | 実装 |
|--------|------|------|
| SEC-001 | パスワードはbcryptでハッシュ化 | NextAuth.js Credentials |
| SEC-002 | セッションCookieはhttpOnly, secure, sameSite: 'lax' | NextAuth.js設定 |
| SEC-003 | ログイン試行は5回/15分に制限 | `src/lib/rate-limiter.ts` |
| SEC-004 | サインアップ試行は3回/1時間に制限 | `src/lib/rate-limiter.ts` |
