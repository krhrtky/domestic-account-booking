# カスタマージャーニー: 家計精算アプリ

## 概要

このドキュメントでは、ユーザーがアプリを使い始めてから継続的に家計精算を行うまでの一連の流れを定義する。

## ペルソナ

### Primary: 田中夫妻（共働きカップル）

- **夫**: 田中太郎（30歳）- ITエンジニア、収入比率 60%
- **妻**: 田中花子（28歳）- マーケティング、収入比率 40%
- **状況**: 財布は別々、食費・光熱費などは共同負担、月末に精算したい
- **課題**: 毎月末にExcelで手計算していて面倒

## Phase 1: 初期セットアップ

### ステップ① サインアップ（両者）

| 項目 | 内容 |
|------|------|
| **アクター** | 太郎（最初に登録） |
| **画面** | `/signup` |
| **入力** | 名前、メールアドレス、パスワード |
| **期待動作** | アカウント作成後、ダッシュボードにリダイレクト |
| **関連機能** | AUTH-001 |

### ステップ② グループ作成

| 項目 | 内容 |
|------|------|
| **アクター** | 太郎 |
| **画面** | `/settings` |
| **入力** | グループ名（任意）、負担割合（60:40） |
| **期待動作** | グループが作成され、太郎がUser Aとして登録 |
| **関連機能** | GRP-001 |

### ステップ③ 招待リンク発行

| 項目 | 内容 |
|------|------|
| **アクター** | 太郎 |
| **画面** | `/settings` |
| **入力** | 花子のメールアドレス |
| **期待動作** | 招待URLが生成・表示される |
| **関連機能** | GRP-002 |

### ステップ④ 招待受け入れ

| 項目 | 内容 |
|------|------|
| **アクター** | 花子 |
| **画面** | `/invite/{token}` |
| **事前条件** | 花子がサインアップ済み |
| **期待動作** | グループに参加し、User Bとして登録 |
| **関連機能** | AUTH-001, GRP-003 |

|------|------|

| **関連機能** | STL-002, STL-004 |

### ステップ⑪ 精算額確認

| 項目 | 内容 |
|------|------|
| **アクター** | 太郎/花子 |
| **画面** | `/dashboard` |
| **表示内容** | 「花子が太郎に¥12,500支払う」等 |
| **関連機能** | STL-001 |

**精算例**:
```
家計支出合計: ¥200,000
├ 太郎支払い: ¥125,000
├ 花子支払い: ¥75,000
└ 共通口座: ¥0

負担割合: 太郎 60% / 花子 40%
太郎の本来負担: ¥200,000 × 60% = ¥120,000
太郎の収支: ¥125,000 - ¥120,000 = +¥5,000

→ 花子が太郎に¥5,000支払う
```

## 代替フロー

### ALT-1: 共通口座からの支出がある場合

**分岐点**: ステップ⑥ 支払元選択

**フロー**:
1. CSVアップロード時に支払元を「Common」に設定
2. 取引は精算計算から除外される
3. 精算サマリーに「共通口座」列として表示される

### ALT-2: パートナーがいない（1人利用）

**分岐点**: ステップ②後

**フロー**:
1. グループ作成後、招待せずに利用開始
2. CSVアップロード・取引管理は可能
3. 精算計算はUser Aのみのデータで実行（実質的に集計機能として利用）

### ALT-3: 後から負担割合を変更

**分岐点**: Phase 5 継続利用中

**フロー**:
1. 設定ページで負担割合を変更
2. 変更後の精算計算に新割合が適用される
3. 過去月の精算は変更後の割合で再計算される（※確認要）

## エラーフロー

### ERR-1: CSV形式エラー

**発生点**: ステップ⑤

**症状**: エラー「必須列が見つかりません」

**回復手順**:
1. 列マッピング画面で手動マッピング
2. 正しい列を選択
3. プレビュー→インポート

### ERR-2: 招待期限切れ

**発生点**: ステップ④

**症状**: エラー「招待の有効期限が切れています」

**回復手順**:
1. グループ作成者に新しい招待を依頼
2. 新しい招待URLで再試行

### ERR-3: レート制限

**発生点**: ステップ①（ログイン）、ステップ⑤（CSV）

**症状**: エラー「試行回数が上限を超えました」

**回復手順**:
1. 指定時間待機
2. 再試行
